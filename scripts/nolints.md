# nolints.json — why each entry exists

`scripts/nolints.json` is read by the lint driver (`batteries/runLinter`,
wired as `lintDriver` in `lakefile.toml`). JSON carries no comments, so the
justifications live here. **Every entry must be listed below with a reason;
an entry without one should be treated as a lint failure in review.**

## `unusedArguments` on `Host.instRepr*.repr` (5 entries)

`Host.instReprVerdict.repr`, `Host.NestingDepth.instReprDepthScan.repr`,
`Host.instReprPrincipalKey.repr`, `Host.instReprEnvelope.repr`,
`Host.instReprAuthenticatedPrincipal.repr`.

All five are compiler-generated by `deriving Repr` on structures. The
derived structure printer renders `{ field := …, … }` braces, which never
parenthesize, so the `prec` argument is inherently unused — this is the
derive handler's code, not ours. The alternative (hand-writing the five
`Repr` instances just to name the argument `_prec`) would put five
field-enumerating instances in TCB modules that silently drift when a
field is added. The linter's own auto-generated-declaration exemption
misses these `.repr` auxiliaries; nolint restores the intended scope.
