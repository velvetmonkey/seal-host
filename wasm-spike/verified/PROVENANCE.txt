Local-rebuild note: the installed Emscripten and Lean sources were used through
the existing wasm-spike build path. The Lean runtime archive, every project and
mcp-seal object, the runtime package objects (including UnicodeBasic), the
stdlib/specialization providers, and the initializer closure were rebuilt from
empty object directories before the strict link. A second strict link
reproduced the wasm hash and generated glue hash
`0802ef0c4237c88dcefbaa4e2bb541e0dc6477ee1b6e3d5e5627e1d50b3bdf0a`
byte-for-byte. Both `seal.wasm` and its generated `seal.js` loader are repinned
as a matched pair and exercised together by the three-way Node lane.
`build_runtime_wasm.sh` source-shape-checks and normalizes Lean 4.28's
`String.data` list terminator from `lean_box_uint32(0)` to the scalar
`lean_box(0)`: the former is only `List.nil` on a 64-bit runtime and becomes a
boxed UInt32 on 32-bit wasm. The normalization is applied to a generated build
copy; the vendored Lean source remains unchanged. This is a same-machine build,
not a clean-runner reproduction; independent clean-runner minting remains the
judge of record.
